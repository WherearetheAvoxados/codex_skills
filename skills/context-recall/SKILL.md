# 맥락 되살리기

코드를 고치지 않는다. 읽고 정리해서 보고만 하고, 끝나면 지시를 기다린다.

## 읽을 것 (서로 무관하니 한 번에)
1. **압축 요약**: 대화 맨 위에 있으면 가장 먼저, 가장 믿을 만한 근거로.
2. **지침**: AGENTS.md (작업 규칙, 승인 순서).
3. **과제 기록**: SPEC.md (목표 · 성공 기준 · 데이터 상태 · 검증 기준값 · 범위 밖 · 미확인), PLAN.md (단위 표와 상태), DECISIONS.md (결정 / 이유 / 버린 대안 / 출처).
4. **구조도**가 있으면 (ARCHITECTURE.svg 등) 글자만: `grep -o '<text[^>]*>[^<]*</text>' <svg> | sed 's/<[^>]*>//g'`
5. **git**: `git status --short`, `git log --oneline -8`.
6. **마지막 실행 결과**: PLAN.md에 적힌 마지막 단위의 검증 명령을 다시 돌리지 말고, 기록된 결과만 본다. 필요하면 다시 돌릴지 묻는다.

## 어긋날 때
기록은 그때의 것이다. 코드 · git과 다르면 지금 상태를 믿고 어긋난 곳을 보고에 적는다 (예: PLAN에는 "다음"인데 이미 구현됨, DECISIONS의 파일이 사라짐).

## 보고 형식 (짧게, 15줄 안팎)
1. **목표와 성공 기준**: SPEC 한 줄 요약 + 기준별 ✓/✗/미확인.
2. **진행**: 끝난 단위, 진행 중 단위, 남은 단위 (PLAN.md 기준).
3. **마지막으로 한 일**: 바뀐 파일, 실행 결과 숫자, 남은 문제, 내 결정을 기다리는 것, 커밋 여부.
4. **걸리는 규칙**: AGENTS.md에서 지금 작업에 해당하는 것만.
5. **바로 다음**: 할 일 1~3개. 기록이 낡았으면 고칠 곳도.
6. **남은 시간 대비**: 시간이 알려져 있으면 남은 단위가 들어가는지, 뺄 것 후보.

확인한 사실과 숫자만 쓴다. 모르는 것은 모른다고 적는다.
