# 원인 쉽게 다시 설명하기

## 지키는 것
- **파일을 바꾸지 않는다.** 설명만 하고 내 답을 기다린다.
- 새 주장을 보태지 않는다. 앞에서 말한 원인을 풀어 쓰는 것이지 새로 진단하는 것이 아니다.
- 다시 보다가 앞 설명이 틀렸거나 근거가 약했으면 숨기지 말고 그렇다고 말한다.

## 무엇을 설명할지
- 직전 답(또는 내가 가리킨 문장)에서 **원인에 해당하는 부분**만. 결과 수치 · 선택지 · 다음 할 일은 뺀다.
- 원인이 여럿이면 가장 중요한 하나만 풀고, 나머지는 한 줄씩 남긴다.
- 확인이 필요하면 코드나 실행 결과를 다시 읽는다. 기억에 기대지 않는다.

## 설명 순서
1. **한 줄 요약**: 전문 용어 없이 한 문장. 비유를 써도 좋다.
2. **무슨 일이 일어났나**: 순서대로, 단계마다 한두 문장. "A 때문에 B" 고리가 끊기지 않게.
3. **예시**: 이 과제의 실제 값 하나(입력 한 줄, 실제 숫자)로 처음부터 끝까지 따라간다. "이랬으면 맞았을 것 / 실제로는 이래서 틀림"을 나란히. 지어낸 예면 지어냈다고 밝힌다.
4. **그래서 무엇이 문제인가**: 내가 본 증상과 원인을 다시 잇는다.
5. (해당하면) **고치는 방향이 왜 원인을 푸는지** 한두 문장.

## 결정 설명일 때 (서술형 대비)
- DECISIONS.md의 그 줄을 기준으로: 무엇을 정했나 → SPEC의 어느 요구 때문인가 → 버린 대안과 버린 이유 → 이 결정의 한계.
- 내가 시험장에서 5분 안에 손으로 쓸 수 있는 길이(5~7문장)로.

## 쉽게 쓰는 법
- 한 문장에 생각 하나. 영어 약어는 되도록 쓰지 않는다.
- 숫자는 꼭 필요한 것만, 크다 · 작다 · 정상이다를 함께.
- 파일:줄은 맨 끝 "근거" 줄에 모은다.
- 앞 설명을 그대로 되풀이하지 않고 다른 길로 설명한다.
- 끝에 "어느 부분이 아직 헷갈리는지" 짧게 묻는다.
