# 요구사항 인터뷰 → SPEC.md

## 지키는 것
- 이 스킬 동안 코드를 쓰지 않는다. 만드는 파일은 SPEC.md 하나.
- 질문은 내가 담당자에게 직접 묻는다. 너는 질문을 제안하고, 내가 붙여 넣은 답을 정리한다.
- 한 번에 질문 3개 이내. 앞 답을 보고 다음 질문을 고른다.
- 답을 추측으로 채우지 않는다. 모르는 것은 "미확인"에 둔다.

## 1. 먼저 읽기 (짧게)
- README(과제 원문, 읽기만), 코드 폴더 구조(파일 목록)를 훑는다.
- **데이터 파일마다** 아래를 짧게 확인한다 (출력은 잘라 받는다). CSV 예, N은 열 번호:
  ```bash
  wc -l f.csv; head -5 f.csv; tail -3 f.csv                                        # 양 · 머리줄 · 끝이 잘렸는지
  cut -d, -fN f.csv | tail -n +2 | sort | uniq -c | sort -rn | head                # 핵심 열(ID · 코드 · 시간)의 고유값 상위
  cut -d, -fN f.csv | tail -n +2 | sed 's/[0-9]/9/g' | sort | uniq -c              # 시간 형식이 한 가지인지 (모양별 개수)
  cut -d, -fN f.csv | tail -n +2 | sort -c && echo 정렬됨                           # 시간 순 정렬 여부 (ISO 형식일 때)
  tail -n +2 f.csv | sort | uniq -c | awk '$1>1{d+=$1-1} END{print d+0, "중복 행"}'  # 완전 중복 행 수
  ```
  - 따옴표 안에 쉼표가 있거나 CSV가 아니면(엑셀 · JSON) python 표준 라이브러리(`csv`, `json`)로 같은 다섯 가지를 본다.
  - 결과는 파일마다 3~5줄로 요약: 행 수, 핵심 열, 형식, 정렬, 중복, 이상한 점.
- **이상한 점은 추측해서 처리하지 않는다.** 빈 값 · 형식이 섞인 시간 · 중복 · 같은 ID에 다른 값 · 말이 안 되는 숫자(음수 수량 등)는 모두 담당자 질문으로 바꾼다. 예: "시간이 `2024-01-02`와 `01/02/2024` 두 형식으로 섞여 있습니다(312행). 둘 다 같은 날짜 체계인가요?"
- 읽은 것으로 이미 답이 나오는 질문은 묻지 않는다.

## 2. 질문 순서 (사소한 것 → 깊은 것)
| 단계 | 알아낼 것 | 질문 예 |
|---|---|---|
| ① 지금 업무 방식 | 지금은 누가 어떻게 하나 | "지금은 이 일을 어떻게 처리하고 계세요?" |
| ② 문제 사례 | 가장 불편했던 실제 한 건 | "최근에 가장 곤란했던 경우 하나만 들려주세요." |
| ③ 데이터 | 입력의 형식 · 양 · 품질, 어디서 오나, **1에서 찾은 이상한 점** | "이 파일은 매번 같은 형식인가요? 중복 행 37개는 지워도 되나요?" |
| ④ 결과 사용자 | 누가 결과를 어디서 보고 무엇을 결정하나 | "결과는 누가 보고, 보고 나서 무엇을 하시나요?" |
| ⑤ 성공 기준 | 무엇이 되면 성공인가 (숫자 · 화면) | "어떤 상태면 '이거면 됐다'고 하시겠어요?" |
| ⑥ 범위 밖 · 우선순위 **(필수)** | 이번에 안 해도 되는 것, 시간이 모자라면 먼저 할 것 | **"이번에 안 해도 되는 것은 무엇인가요?"** (이어서 "시간이 부족하면 무엇부터 보여 드릴까요?") |
| ⑦ 확인 방법 **(필수)** | 담당자가 결과를 맞다고 판단하는 방법과 숫자 | **"결과가 맞는지 어떻게 확인하시나요?"** (이어서 "그때 보시는 숫자가 있나요? 예: 지난달 합계") |

- **⑥과 ⑦은 시간이 모자라도 빼지 않고 마지막에 반드시 묻는다.** ⑦의 답에 나온 숫자는 SPEC "검증 기준값"에 그대로 적는다.
- 답이 모호하면 같은 단계에서 "예를 들면?"으로 한 번 더 파고든 뒤 넘어간다.
- 성공 기준은 확인할 수 있는 말로 바꿔 되묻는다. 예: "빠르게" → "1초 안에 화면에 뜨면 될까요?"
- 3시간 과제라면 ①~⑦을 질문 7~10개 안에 끝낸다.

## 3. SPEC.md 쓰기
```markdown
# SPEC
## 목표
- (한 문장: 누가, 무엇을, 왜)
## 성공 기준 (확인 방법과 함께)
- [ ] 기준 — 확인: 실행 명령 / 화면 / 숫자
## 데이터 상태 (1에서 찾은 것)
| 파일 | 발견한 문제 (행 수 · 예) | 처리 방식 | 근거 |
|---|---|---|---|
| sales.csv | 완전 중복 37행 | 지운다 | 담당자 답 (③) / 미확인이면 "미확인: 남겨 둠" |
## 검증 기준값 (담당자가 확인해 준 숫자)
| 항목 | 값 | 확인 방법 (담당자가 말한 대로) |
|---|---|---|
| 10월 전체 매출 합계 | 12,345,000원 | 담당자의 월말 보고서와 비교 |
## 범위 밖
- 이번에 하지 않는 것 (담당자 답 근거)
## 우선순위
1. 시간이 모자라면 이것부터
## 미확인 사항
- 아직 모르는 것 — 내가 정한 가정 (나중에 담당자에게 확인)
## 근거
- 질문 → 답 요약 한 줄씩
```
- 성공 기준마다 확인 방법을 붙인다. 붙일 수 없으면 기준을 다시 묻는다.
- "데이터 상태"의 처리 방식은 담당자 답이 있을 때만 정한다. 답이 없으면 "미확인"으로 두고 데이터를 바꾸지 않는다.
- "검증 기준값"에는 담당자가 말한 숫자만 적는다. 내가 계산한 값을 기준값으로 쓰지 않는다. 숫자를 못 받았으면 "없음 (⑦ 답: …)"이라고 적는다.
- 가정은 "미확인"에 적고 DECISIONS.md에도 `가정 / 이유 / 다른 가능성 / 출처` 한 줄로 남긴다.

## 4. 끝내기
- SPEC.md를 보여 주고 "빠진 것 · 틀린 것"을 묻는다.
- 내가 확정하면 끝. 계획 · 구현은 내가 따로 부른다($impl-steps, $follow-plan). 스스로 시작하지 않는다.
