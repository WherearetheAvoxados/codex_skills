# 구현 단계 표 만들기 · 갱신

## 1. 찾기와 읽기
- PLAN.md의 단계 표를 찾는다. 없으면 SPEC.md의 성공 기준에서 단계를 뽑아 새로 만든다: 끝에서 끝까지 가장 얇게 도는 것 먼저, 단계마다 검증 명령과 기대 결과, SPEC에 없는 것은 "제안만".
- 진행 근거: 실행 결과(명령과 숫자), `git log --oneline -10`, 지금 대화. **근거 없이 "완료"로 바꾸지 않는다.**

## 2. 표 형식
```markdown
## 구현 단계 (MM-DD HH:MM 기준)
| # | 단계 | 검증 (명령 → 기대) | 결과 | 상태 |
|---|---|---|---|---|
| 1 | 최소 동작: 화면까지 | `python app.py` → 표 1개 | 표 1개 뜸 | ✅ 완료 |
|   | ① 하위 단계 | ... | ... | 🟡 진행 중 |
| 2 | 실제 데이터 | `pytest -q` → 3 passed | | 🔴 다음 |
| 3 | (시간 남으면) 정렬 | | | ⚪ 미착수 |
| - | 계획 밖: 엑셀 내보내기 | | | ⚪ 제안만 |
```
- 상태는 다섯 가지만: ✅ 완료 · 🟡 진행 중 · 🔴 다음 · ⚪ 미착수 · ⚪ 보류/없앰/제안만 (글자로 구분).
- **🔴 다음은 한 번에 하나.** 끝나면 ✅로 바꾸고 다음 줄로 옮긴다.
- 하위 단계(①②…)는 번호 칸을 비운다.
- 결과 칸에는 실제로 본 숫자 · 출력 한 줄. 핵심 숫자가 있으면 단계 이름 뒤에도 붙인다 (예: "② 응답 0.3초 ✓").
- 계획에 없던 일은 맨 아래 번호 "-"로. 요구사항에 없는 것은 "제안만"으로 두고 구현하지 않는다.

## 2-1. 그림: docs/architecture.svg 오른쪽 (기본, 표를 고칠 때마다 함께)
- 내가 눈으로 보며 작업하려고 그린다. 기준은 PLAN.md(검증 명령 · 결과 칸까지)이고, 그림은 그 표를 옮긴 것이라 내용을 따로 만들지 않는다.
- 같은 파일 왼쪽은 구조도($arch-diagram). 파일이 없으면 arch-diagram의 틀로 먼저 만든다(왼쪽은 비워 두고 구조도를 그리자고 말한다).
- `<!-- implementation steps -->` 주석 아래만 고친다. 제목 y=32, 첫 줄 y=70, 줄 간격 30.
```svg
  <!-- implementation steps -->
  <text x="760" y="32" font-size="14" font-weight="600" fill="#2C2C2A">구현 단계 (MM-DD HH:MM 기준)</text>
  <!-- 단계 한 줄 -->
  <text x="776" y="Y" font-size="12" font-weight="600" fill="#2C2C2A">1</text>
  <text x="806" y="Y" font-size="12" font-weight="600" fill="#2C2C2A">최소 동작: 화면까지</text>
  <rect x="1150" y="Y-14" width="66" height="20" rx="10" fill="F" stroke="S"/>
  <text x="1183" y="Y" font-size="11" text-anchor="middle" fill="T">완료</text>
  <!-- 하위 단계: 번호 없이, 이름 x=806 · font-weight 없음 · fill #444441 -->
```
| 상태 | fill (F) | stroke (S) | 글자 (T) |
|---|---|---|---|
| 완료 | #EAF3DE | #3B6D11 | #27500A |
| 진행 중 | #FAEEDA | #BA7517 | #633806 |
| 다음 | #FFFFFF | #A32D2D | #A32D2D |
| 미착수 · 보류 · 없앰 · 제안만 | #F1EFE8 | #888780 | #444441 |
- 이름은 알약(x 1150)에 닿지 않게 한 줄 25자 안팎. 검증 · 결과 칸은 그리지 않고 핵심 숫자만 이름 뒤에 붙인다.
- 계획 밖 줄은 "계획 밖" 소제목(한 줄 띄움) 아래 번호 "-"로.
- 표가 왼쪽보다 길어지면 높이 H(= 큰 쪽 맨 아래 + 40)와 `<svg height viewBox>` · 배경 rect · 구분선을 함께 늘린다.

## 3. 고칠 때
- 줄을 더하거나 빼도 번호가 꼬이지 않게 맞춘다.
- 제목의 "기준" 시각을 지금으로 고친다.
- docs/architecture.svg 오른쪽도 같은 내용으로 함께 고친다. 줄을 더하거나 빼면 그 아래 오른쪽 줄(x ≥ 760)의 y를 모두 30씩 옮긴다(python으로 그 구역만).
- 그림의 알약 색이 PLAN.md 상태와 같아야 한다(✅ 완료 · 🟡 진행 중 · 🔴 다음 · ⚪ 나머지).
- 구조도(arch-diagram)의 상태 색과 표의 상태가 어긋나면 함께 맞추자고 말한다.
- 계획 자체가 바뀌었으면(단계 추가 · 삭제) DECISIONS.md에 `바꿈: X / 이유 / 버린 대안 / 출처` 한 줄.

## 4. 확인
- 표가 깨지지 않았는지(칸 수) 다시 읽는다.
- SVG: `python -c "import xml.dom.minidom,sys; xml.dom.minidom.parse(sys.argv[1])" docs/architecture.svg`. 넘침 어림: 한글 1자 ≈ 12px, 영문 · 숫자 ≈ 0.6배로 알약(x 1150)에 닿지 않는지.
- 바뀐 줄을 짧게 보고한다: 무엇이 ✅가 됐고, 무엇이 🔴 다음인지, 남은 시간에 들어가는지. 끝에 "docs/architecture.svg를 열어 확인" 한 줄.
